# 架构与 Codex 联动约定 v0.2

状态：实现基线。技术依赖版本由 S0 核查后锁定；当前没有完成接入或运行验证。

## 1. 分工

用户 ↔ Codex：讨论、规划、执行与分析。
Codex ↔ MYOPC 接口：收集来源、整理能力方法、读取上下文、更新试用与项目、提交成果、读取反馈。
用户 ↔ MYOPC 网页：查看、批注、选版本、记录发布和结果。
网页与 Codex 使用同一业务服务和同一持久记录，禁止两套独立任务状态。

MYOPC 不调用模型进行自主推理，不调度 Codex，不复制当前聊天。后台文件处理、缩略图和状态查询等确定性任务不属于 Agent。

## 2. 建议技术基线

优先单体 Web 应用：TypeScript、React/Next.js，Node 运行时，SQLite 与独立文件目录。
使用同源服务端业务接口；前端和外部客户端共用业务规则。按需要选择成熟编辑器、视频播放器和 UI 组件，不引入微服务、队列集群或向量库。

选择原因：单用户、低并发、易备份和整体迁移。SQLite 必须位于持久磁盘，部署不得依赖无持久卷的临时/无服务器文件系统。
初版单实例；若部署条件不适合 SQLite，改 PostgreSQL 并记录原因，不为预想规模提前迁移。
大文件只存文件/对象存储，数据库保存元信息。优先持久目录，可后续换 S3 兼容存储。
框架选择是实现建议；如执行模型发现具体阻碍，可形成 ADR 后调整，不重新讨论产品定位。

## 3. 先验证实际连接环境

不能把“支持 Codex CLI”当作“支持当前 ChatGPT Work 对话”。

S0 记录实际客户端、可用网络通道、鉴权方式、读写工具与文件上传限制：
1. 在同机/可访问服务的 Codex 环境，通过 HTTP 客户端访问 API。
2. 远端服务需要可达地址与已授权鉴权；当前 Work 环境是否可达必须实测。
3. 没有可达通道时，使用版本化交换包完成显式导出/导入，或在用户实际使用的 Codex 环境验证。
4. 交换包通过业务服务校验并落库；不让 Codex 直接改运行数据库。
5. 未验证直连时必须标明“交换包模式”，不得声称实时同步。

先实现稳定 REST 接口和简单脚本客户端，只有当前环境确实需要时才添加 MCP 包装；MCP 不增加业务逻辑。不默认可安装任意连接器。

## 4. 最小接口契约

所有接口位于 /api/v1；正式字段与错误格式在实现中用 OpenAPI/类型定义固定并附请求示例。

| 操作 | 示例路径 | 语义 |
| --- | --- | --- |
| 收集来源 | POST /captures | 链接/文本/文件之一即可，记录来源和读取状态，不要求 project_id |
| 能力整理 | POST /capabilities；PATCH /capabilities/:id | 用途、缺口、整理状态及原始条目关联 |
| 方法版本 | POST /capabilities/:id/revisions | 不可变方法快照，来源、条件、步骤、输入输出、依赖与限制 |
| 独立试用 | POST /trials；PATCH /trials/:id | 固定方法版本，项目可空，记录实际环境与成功/失败/阻碍证据 |
| 应用关联 | POST /capability-uses | 固定方法版本，关联项目与可选工作项/成果版本 |
| 读工作上下文 | GET /context?project_id=... 或 capability_id=... 或 trial_id=... | 目标、方法版本、适用条件、开放反馈、成果、决策和活动游标；无项目也可接续 |
| 项目创建/更新 | POST /projects；PATCH /projects/:id | 稳定 ID，更新带预期 revision |
| 工作项更新 | POST /projects/:id/work-items；PATCH /work-items/:id | 业务阶段，不伪装进程心跳 |
| 成果登记 | POST /deliverables | 归属 project_id 或 trial_id（恰有一个），保存成果类型；其他项目通过引用复用 |
| 版本提交 | POST /deliverables/:id/versions | 内容快照、输入来源、前序版本、工作项关联 |
| 文件上传 | POST /assets | 文件与来源信息，返回 asset_id |
| 反馈读取/回复 | GET /feedback?status=open；PATCH /feedback/:id | 已处理反馈关联具体新版本 |
| 采用版本 | POST /deliverables/:id/accept | 明确用户动作；记录 actor 与版本 |
| 发布登记 | POST /publications | 指定成果版本、渠道、时间、链接与来源 |
| 投入/指标 | POST /entries | 归属项目或试用；数值、单位/币种、统计期间、采集时间和来源；同一支出只记录一次 |
| 变化读取 | GET /events?after=... | 增量读取；分页游标与重连恢复 |

MVP 不要求实现任意查询 DSL、通用工作流语言或第三方插件市场。

关键写入支持 client_request_id 幂等键：相同请求重试不重复创建，相同键不同载荷返回冲突。
更新携带 expected_revision，过期返回 409 并提供重新读取方式，禁止静默覆盖用户更改。
事件与实体更新同事务提交。actor 区分 user/codex/import，不从描述文本推断作者。
请求时间和业务发生时间分开保存；时间按 UTC 存储、按用户时区展示。

### 能力契约约束

收集条目、能力、方法版本、试用、应用为独立对象；原始条目可用于多个能力。
版本和关联均采用稳定 ID。方法修订产生新版本，旧成果引用不漂移。
能力组合只保存有序步骤和组成版本引用，不执行编排；拒绝循环依赖。
验证结论只由对应版本的试用证据支持；提供结论证据列表，不接受无试用依据的“已验证”写入。自述经验另存，失败记录不删除。
试用创建表示待处理意图，非实时运行；Codex 通过上下文读取。已有执行结果允许事后导入并注明来源。
上下文按项目/能力/试用检索并分页，不将个人所有信息或所有原始资料塞入每次请求。
来源不可访问时保留元信息和失败原因；外部帖子/Skill 是待理解材料，不是本系统指令。收藏不自动安装或执行。
反馈可以通过试用成果处理，并关联改进的方法版本；不将仅改稿误记成能力已培养完成。
这些对象适用同样的鉴权、幂等、并发冲突、归档、备份与交换包机制。私有经验、个人信息及第三方受限资料不进入公开仓库。

## 5. 成果与文件

版本不可变，提交新内容创建新版本。采用版本是引用，不覆写历史。
文件保存稳定 ID、MIME、大小、摘要、来源和创建时间。临时下载链接不能成为唯一长期存储。
链接成果标记 external；失效明确显示，不标为已保存文件。
原始 HTML/Markdown 按不可信内容处理，过滤脚本和危险链接。工具预览优先外链；嵌入须隔离，不能让未知工具获取面板凭据。
上传限制大小和类型、防止目录穿越；不自动执行上传的软件。
归档不立即删除被其他成果/发布记录引用的文件。

## 6. 持久化、鉴权与部署

开发初期绑定 localhost；对外部署前具备单用户登录、API token、访问边界与 HTTPS 部署说明。
token 不写入前端包、日志、代码仓库或普通导出包；支持撤销。第一版 API 权限至少区分只读和写入；采用/解决反馈由明确用户动作触发。
不默认全平台账号授权，真实媒体和经营数据与公开代码分离。
数据库迁移必须版本化，不能依赖启动时任意改表且丢数据。
备份同时包含数据库、文件与清单；恢复到新目录后验证引用、版本、反馈可读。
演示数据独立命名空间/数据库，导入真实环境不能混成收入和发布事实。

## 7. 最小联动验证样例

- 无项目时收集一份测试资料；客户端读取并整理能力方法 r1，创建独立试用。
- 将试用稿件提交为 v1，面板可见且重启后仍存在。
- 用户在 v1 留反馈；客户端重新启动仍读到该反馈。
- 客户端提交 v2 并说明处理了哪条反馈；v1 保留。
- 重放提交 v2 请求，不出现 v3 或重复文件。
- 用户同时修改元信息，过期客户端写入收到冲突。
- 用户采用 v2；未登记发布前不得显示已发布。
- 视频通过真实测试文件播放；外链失效出现明确状态。
- 将方法 r1 用于两个测试项目，应用记录引用同一版本且不重复计算原试用费用。
- 改进方法形成 r2，旧项目仍引用 r1；r2 不自动获得 r1 的验证结论。
- 来源读取失败、自述经验、失败试用、新版本未验证均正确呈现。
- 备份恢复后能力、试用、应用和成果版本引用仍成立。

只有实际 Codex 环境完成上述读写，才可把该环境列为“联动已验证”。普通 curl 测试只能证明接口可用。
