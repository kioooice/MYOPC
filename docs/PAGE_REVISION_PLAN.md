# 页面修改方案：让内容成为主角

状态：待实施。本方案独立于 reading-note-v5 加工规程变更；本轮不修改页面代码。

## 目标与范围
保留现有浅色、绿色强调色、左侧导航和总览 / 项目 / 工具 / 空间结构。让用户先看到用途、进展和观点，来源与运行细节按需展开。继续由服务器拉知识仓库、调用 API 生成内容，页面读取已保存结果。

## 各页调整
| 页面 | 主体内容 | 操作与次要信息 |
| --- | --- | --- |
| 总览 | 在推进的项目、常用工具入口、最近更新的知识各一块；数量作为辅助 | 项目优先进行中，再展示验证中；暂停项目去项目页查看。未设置常用工具时展示现有工具，不虚构使用频率 |
| 项目 | 项目名、用途、当前阶段、材料明确的关键限制或进展 | 状态保留，按钮改“查看项目”；应用入口与源码地址分别命名 |
| 工具 | 工具名、适用场景、能做什么 | 有明确实例地址时主按钮“打开工具”，次按钮“查看说明”；只有源码时明确“查看源码”，入口缺失不做假按钮 |
| 空间 | 标题、核心观点、适用场景，保留方法 / 经验 / 判断筛选 | 卡片不突出通用“待验证”徽标；正文摘要仍保留“建议”“当时采用”等必要限定，证据状态在详情可见 |
| 详情 | 先呈现完整说明，随后展示有内容的做法、依据与适用条件 | 原文、来源版本、加工信息折叠但可直接展开；无内容栏目隐藏 |

## 卡片共同规则
- 去掉常态“已有阅读说明”；文件路径和原文地址移入详情。
- 更新日期降为底部辅助信息，不与标题和摘要争夺注意力。
- “查看原文与说明”按条目改成“查看项目 / 查看说明 / 阅读笔记”。
- 摘要使用已保存的 card，不由前端删除关键词来“美化”。无生成结果时显示原 summary，并诚实标注使用原文摘要。
- 待更新、加工失败保留可见的轻量提示；有旧结果时说明正在展示旧说明，不能伪装为最新内容。
- 卡片高度随内容合理收敛，避免为了底部按钮对齐制造大片空白；窄屏一列、不截掉必要条件。

## 总览与运行提示
- 总览的项目顺序与项目页使用同一状态顺序，暂停项目不占据首屏主要位置。
- 知识区按更新时间展示，称“最近更新”，不将一次批量整理误称为新发现或推荐。
- 顶栏将“知识 12:15”改为“上次同步 12:15”，可展开查看来源版本、待更新数量和错误。
- 同步、加工可以保留在顶栏的更新区，主内容卡片不重复显示这些管理状态。
- “共享工作状态 / Codex 驱动”若无对应实时功能则删除或移到关于，不用常亮绿点暗示 Agent 正在工作。

## 示例（表达目标，不写死进前端）
任务之后值得留下什么：
留下新理解、关键选择和踩坑经验；重复做法稳定后，再整理成方法或技能。没有新东西时，更新已有记录即可。

## 实施与验收
先调整卡片共同信息，再调整总览排序与入口语义，最后整理详情层级。无需新增问答入口、网页编辑、收藏系统或数据库结构。
- 项目状态和真实使用限制没有被短摘要抹去。
- 工具按钮打开的地址与名称一致；源码不伪装为实例入口。
- 最新、待更新、加工失败和无说明四种状态均能理解。
- 笔记列表直接展示观点，不充满“这是一条笔记”及重复状态套话。
- 宽屏与窄屏检查总览、三类列表及至少一条详情。
- 页面验证与真实模型摘要效果分别验收；加工 ready 不能代替内容质量检查。
