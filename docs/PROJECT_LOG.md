## 2026-09-10 / 09-11 OPC 改为读取知识仓库并生成阅读说明

**新增进展**

- OPC 从"自建素材与行动的工作台"改为只读独立知识仓库 `kioooice/MYOPC-Knowledge`：同步时先 `git fetch` 并只允许快进，再解析 `projects/`、`tools/`、`notes/` 下的 Markdown 建立索引。
- 新增"阅读说明"规程：`deepseek-flash` 按固定提示词输出结构化结果（原文事实、关键选择与依据、步骤、适用条件、仍未确定、模型推断），结果存 SQLite，附来源哈希与规程版本。
- 新增 `knowledge_entries`、`knowledge_reading_notes`、`knowledge_sync_state` 三张表，以及 `GET /api/v1/knowledge`、`GET /knowledge/entries/:id`、`POST /knowledge/sync|notes|process`。
- 页面：总览 + 项目 / 工具 / 空间三块改为知识条目视图；条目详情展示阅读说明、原文、来源与入口。历史业务数据（素材、方法、行动、成果、反馈）保留可查，不再进入主要流程。
- 首页三档文字都由模型生成：`brief`（≤24 字，首页一行）、`card`（列表卡，目标 90 字，按句收边兜底 110 字）、完整说明（详情页）。规程由 v1 演进到 v4。

**关键决策与理由**

- 内容放独立仓库：知识可以独立保存和使用，换展示工具或让其他 Agent 读取时不必搬动整套应用；也因此不做网页编辑和 Git 双向同步。
- 同步按钮必须真的拉取：此前按钮只重读服务器上已有检出，用户点完仍看到旧内容；改成按钮内 `git fetch` + 快进后与"同步"的语义一致。
- 升级 `better-sqlite3` 到 13.x：崩溃根因在 Node 24 的清理钩子回归（nodejs/node#65446），13.x 改用 N-API 后不再触发。

**已验证**

- `npm test` 34 项、`npm run lint`、`npm run build` 通过；知识解析、同步幂等、删除不可见、模型失败保留上一次结果、拉取快进均有测试覆盖。
- 服务器 `124.222.190.89`：容器 `myopc` + OpenResty `:3010`（Basic Auth），知识仓库只读挂载（同步需要快进时为可写），`opc-knowledge-sync.timer` 每 30 分钟拉取并加工。
- 实测：16 条条目全部生成阅读说明；无更新时一次同步约 5 秒（几乎全为到 GitHub 的网络往返）；页面同步实测将检出从 `787baa9` 归并到 `2fcb520`。
- 稳定性：旧版 `better-sqlite3` 12.4.1 下容器崩溃 3 次（原生 abort 堆栈），升级到 13.0.3 后 300 次接口请求 + 2 万次语句 GC 压测无 abort，容器 `RestartCount=0`。
