# 阶段计划与验收 v0.3

状态：现有状态文档标记 S0 未开始。以下为可修订计划，不是完成记录。
规划模型负责整体理解、取舍和验收；开发模型负责实现与证据。用户自然提出变化，不承担技术方案和变更分类工作。

## 推进原则

以完整使用过程为单位：S0 一轮真实往返 → S1 跨轮复用 → S2 外部反馈进入下一轮。
阶段是当前组织方式，不是僵硬审批流水线。阶段内连续执行，常规选择自行处理；阶段结束同步仓库、证据和状态。
S0 证明连接与一次使用可行，不能据此宣称整个循环成立。S1 必须有第二次实际应用。S2 再验证经营反馈。
图文、视频和工具是不同载体，不是独立建设三个系统。

## S0：一轮使用与最小联动

目标：用低成本真实样例，走通输入/需求 → 行动 → 成果 → 反馈 → 留下下一步。
实施：
- 从产品规格的三个场景选择最小图文样例，并写明另两个入口如何共用记录，不先建全部菜单。
- 初始化最小可运行应用、持久化和简单客户端。实现必需的来源/目标、方法或素材引用、尝试、成果版本、反馈及后续决策。
- 界面支持阅读与反馈；客户端读上下文、提交产物、读取反馈并更新结果。
- 实测用户实际 Codex 环境的网络和鉴权；不能直连时验证显式交换包并标明降级状态。
- 固定已实现契约与依赖版本，补运行说明；未实现接口保留候选状态。

验收：
- 一次实际客户端往返有证据，稿件版本和来源可查看。
- 本轮反馈形成有依据的下一步，标为拟议，不冒充已执行。
- 重启后记录存在；重试不重复创建；过期写入不会覆盖用户变更。
- 没有项目/完整能力档案也能开始。未知来源和未知结果不编造。
- API 脚本测试与实际 Codex 接入分别标记，mock 不代替联动验收。

不要求购买 GPU、不建画布、自动平台连接或全量能力管理。H3 仅为场景参考。

## S1：第二轮确实使用第一轮积累

目标：证明工作台让下一轮拥有不同的起点，形成可日常使用的业务体验。
实施：
- 新会话创建第二次尝试，读取第一轮方法、素材、反馈和决策；完成实际应用。
- 按真实使用整理总览、连续工作区、能力与成果视角；以减少跳转和重复录入为准。
- 支持由 Codex 发起的发现、需求、失败三种入口，不在面板设置收集到项目的强制六步表单或重复输入框。
- 扩展图文平台稿、视频预览、工具体验链接，共用版本/反馈/来源机制。
- 增加项目应用与独立试用关系、基础投入和发布记录。
- 完成单用户访问控制、失败状态和备份恢复；运行数据独立于公开代码。

验收：
- 第二次尝试有实际产物；明确引用第一轮什么积累、为何采用、改变或保留了什么。
- 仅写复盘、仅复制方法、仅建立链接不能算跨轮应用；不要求虚构“效果提升”。
- 同一成果在能力/项目/复盘视角一致；方法更新不漂移旧引用，验证结论不自动继承。
- 从需求和失败进入也能完成行动与回填，不强迫补虚假档案。
- 三种成果能真实预览/访问；1366×768 与 1920×1080 核心操作无遮挡。
- 备份恢复可保留跨轮关系；试用费用不因复用重复累计。
- 采用、发布、实时运行和商业效果明确区分。
- 记录用户是否减少寻找和重复维护，若面板增加负担须修正。

## S2：外部反馈改变后续行动

目标：一项真实经营尝试对外发布，外部反馈进入下一次选择与行动。
实施：
- 使用实际已有/新收集能力推进真实内容或工具，用户主动完成发布。
- 记录来源明确的发布表现、使用反馈、咨询或收入；反馈缺失如实标记。
- Codex 与用户区分方法/环境问题和用途/需求假设，提出依据明确的调整。
- 执行适合继续的下一轮；若决定暂停，则如实记录决策，后续执行保持未发生。
- 将可复用方法、适用边界与素材回填，供未来工作读取。

验收分别记录：
1. 能力循环：实际完成过什么、能复用什么、条件和证据。
2. 价值反馈：实际发布及外部观察，不能用内部审阅冒充。
3. 反馈应用：后续实际行动如何受影响；仅决定暂停不伪称二轮执行通过。

没有收入不等于失败；尚未发布或无外部反馈时不能关闭对应经营验证，但继续完成其余已授权工作。
不要求盈利或强行制造改进，不以技术功能完成代替价值判断。

## 后续方向

局部创作画布、AutoDL 状态连接、平台指标导入、增强检索、Observer/Helm 连接、移动端。
只写用途与触发条件，临近实现再细化。不提前设计全部 API、个人数据仓库或循环编排引擎。

## 文档与范围变化

- 仅有文档：直接整合、重写、删去过时设计，不要求新增审批。
- 已有原型/代码：检查调用方与已实现契约，保护可复用部分，同步实现和验证。
- 已有真实数据：识别迁移、备份恢复和历史引用影响。
- 已涉及外部承诺、付费或发布：明确实际代价与所需授权；已有授权继续有效，不重复确认。

已明确目标、当前设计、待验证假设分开表达；这些分类不是永久冻结。
新输入由规划模型判断局部/整体影响，不能只追加新模块。规划更新不等于代码已完成。
不要为迎合已有实现而静默降低验收标准。

提交并推送后核验远程。更新 STATUS，区分技术完成、能力复用、经营反馈。
开发前以最新仓库为准；若已有在途实现，先评估与 v0.3 的差异，不默认推倒重来。
