# 阶段计划与验收 v0.1

当前状态：S0 未开始；所有阶段均为计划，不是完成记录。
开发模型负责实现，规划模型负责阶段规划与验收。用户参与产品判断与成果选择，不承担测试员和接口设计师职责。

## 总体顺序

S0 联动与业务样例验证 → S1 可用工作台 → S2 真实经营闭环。
按完整阶段连续推进，阶段内可分内部任务；不要把每个内部任务变成用户确认点。
阶段结束提交代码、更新状态、保留证据，再进入下一阶段。高优先级缺陷先修复，不靠扩展功能掩盖。

## S0：最小纵向链路

目标：验证实际执行环境能否与持久工作记录衔接。
范围：
- 初始化可运行单体、数据库迁移、测试存储与最小页面。
- 项目、成果、版本、反馈、活动的最小业务模型。
- 实现读上下文、提交版本、添加和读取反馈；简单 HTTP 客户端。
- 用一条图文样例走通完整往返。
- 明确部署位置、实际客户端、网络和鉴权路径。当前环境不可达时记录阻碍并验证显式交换包，不伪称直连完成。

验收：
- 面板阅读 v1 → 留反馈 → 实际客户端读取 → 提交 v2 → 页面看到 v2 和 v1。
- 重启持久化、重试幂等、并发更新冲突测试通过。
- 有一条完整运行证据，列明测试环境及客户端；仅 mock 不通过联动验收。
- 交换包仅可获得“降级链路通过”，直连项目保持未验证。
- 产出最小运行说明、契约和实际架构决策。

不要在此阶段加入画布、社交平台、GPU 调度或经营图表。

## S1：可以日常使用的工作台

目标：用户可以管理图文、视频、小工具三个方向，主要动作不依赖重复录入。
范围：
- 经营总览、项目工作区、成果详情、素材、基础复盘。
- 图文阅读与版本比较；视频播放和版本选择；工具体验/下载链接。
- 开放反馈、采用版本、归档、来源关联。
- 发布记录、时间和费用记录、基础指标；未记录与零值区分。
- 上下文接口和增量事件；错误、附件失效、空状态、断线重试。
- 单用户访问边界、备份恢复、私有运行数据隔离。

验收：
- 产品规格的三个故事均走通；每种成果有真实可预览的测试文件/链接。
- 用户反馈在新会话接续，不要求复制粘贴整段旧聊天。
- 采用和发布状态独立；发布记录始终引用当时的版本。
- 不同渠道、币种、统计期间不被错误合并。
- 1366×768、1920×1080 核心页面无遮挡；桌面完整流程浏览器验证。
- 恢复到新目录后，稿件、媒体、版本及反馈仍可访问。
- 演示数据可辨识且可清理，不混入真实统计。

## S2：第一轮真实经营闭环

目标：至少一个实际项目从准备走到用户主动发布，再留下一次反馈或复盘。
范围：
- 用真实业务验证 S1，优先修复找成果、看版本、反馈接续、录入成本等摩擦。
- Codex 负责可完成的准备与整理，平台发布由用户操作。
- 用户尚未发布时，记录等待实际发布；不要用模拟发布关闭阶段。
- 首轮不要求盈利，不承诺播放、咨询或收入。
- 将重复使用中有效的读写流程整理为接入说明；是否建设 skill 按真实需求另行处理。

验收：
- 有真实产物、实际发布记录和明确来源的反馈；尚无反馈时如实标记，商业闭环仍待完成。
- 能追溯结果来自哪个版本、投入记录是什么、下一步决定是什么。
- 复盘记录面板减少了哪些重复操作、仍有哪些需要手工录入。
- 技术验收与经营验证分别记状态；用户行动未发生不阻塞其余已授权开发。

## 后续候选，非承诺范围

局部创作画布、AutoDL 任务状态连接、平台指标导入、跨项目素材复用增强、Observer/Helm 连接、移动端体验。
进入条件：真实场景反复出现缺口，有明确输入输出，能说明对主线的收益。
优先复用确定性工具和接口，不引入第二个 Agent 系统。

## 阶段报告格式

- 起始与结束提交、分支、实际远程同步情况。
- 完成的用户故事和对应页面/API。
- 运行环境、实际客户端与验证命令。
- 关键证据（脱敏截图、测试摘要、请求结果），区分自动测试和实测。
- 已知问题、未验证内容、阻碍与下一阶段范围。
- 对规划的变更及理由；不得将计划文字直接改成“已完成”。

## 开发模型的第一项任务

阅读 README、AGENTS、产品规格、架构、当前状态并检查仓库最新提交。
执行 S0 全阶段，先验证最小往返，再完善实现。用户已经确认产品定位，不重复要求其选择数据库或接口。
遇到常规技术选择自行决策并记录；需要账号登录或环境授权时，先完成可做工作，再说明具体缺口。
完成后提交并推送，更新 STATUS，给出规划模型可复核的证据。
