# 阶段计划与验收 v0.4

本轮目标：真实项目跨电脑接续。本文是目标与通过条件，不是逐文件施工单；实现状态见 STATUS。

## 当前阶段：共享状态与真实接续

用户有两台电脑，各有本地项目，已有私人服务器站点，逐步趋向服务器使用。保留已有实现，先让一个真实项目在不同工作环境继续推进，不先扩展更多菜单。

使用场景：Codex 在环境 A 基于真实项目完成一份可审阅成果，把项目、相关代码版本、成果、反馈和下一步留在共享服务。环境 B 从新会话、不同本地目录读取同一项目，核对代码与工作状态后继续；面板能看到新版本和需要判断的事项。服务器更新与重启后记录仍在。不依赖 A 的原对话或绝对路径。

执行模型先核对仓库、本地改动、服务器与已有授权，简短记录对场景的理解、主要阻碍、最小方案与取舍，随后连续实现、验证、自纠错和交付。无需等规划模型在线批准常规方案。可以质疑规划并提出更优实现，但不得静默降低通过条件。下面的发现是证据，不是修完即完成的任务清单。

### 已知审查依据

基于 8a0d257 的审查：
- s0-client 恢复流程使用固定第二版并处理所有开放反馈；只能证明固定样例的传输，不能证明针对实际反馈修改。
- 项目介绍按名称/本地路径硬编码；行动未关联项目，项目详情与成果链路脱节。
- 页面缺少外部写入后的刷新机制；进行中范围不一致，待处理混淆用户审阅与 Codex 待改，网络异常可能使提交按钮持续禁用。
- 项目详情偏介绍，缺少当前目标、最新成果与下一步；不必重做视觉，应让真实工作占主要位置。
- 现有业务测试 6/6 通过，不代表线上接续成立。

### 通过条件

1. 稳定项目身份不依赖单机路径。同一项目可记录不同环境位置和仓库/部署入口；介绍可作为业务数据更新。不强制所有尝试归属项目。
2. 两端 Codex 通过明确的连接说明或通用客户端读取服务器上下文、提交任意实际成果；无需改工作台源码，也不另建 Agent。凭据不进仓库。
3. 一个真实项目完成成果 v1 → 新提出的具体反馈 → 针对性 v2。保留版本与处理依据，不把 AI 自测意见冒充用户反馈，不把已处理自动当作用户已接受。再换一条反馈或继续一轮，排除固定文案/固定请求键只能演示一次的问题。
4. 新环境从共同状态接续，能找到目标、准确成果版本、开放反馈、代码提交与下一步；本地未提交内容不会被伪称已同步。代码推送和工作记录写入的部分失败可识别、可恢复。
5. 面板可获得外部最新变化，更新方式明确；状态计数一致，待审阅与待修改可辨，断线/失败后能恢复操作。
6. 使用独立开发/测试数据；现有正式记录在兼容迁移、重启与更新后保留。备份可恢复到隔离目录并验证关系；SQLite WAL 模式不可用运行中裸复制单个数据库文件充当可靠备份。
7. 交付包含代码推送核验、实际部署提交、适当的业务测试与浏览器证据，以及未验证边界。不能用仓库配置推断服务器实际配置。

### 无人值守与环境限制

- 在已授权范围内连续完成整个阶段，普通技术问题自行解决；不因需要用户提供真实审阅而停止其他工作。
- 用户不在线时，用清楚标记的测试反馈验证技术链路，真实用户反馈与采用保留待验；不得代替用户接受成果。
- 第二台实机暂不可达时，可用两个独立工作目录/客户端和新会话上下文验证接续机制，记录隔离方式；仅算替代验证，不宣称两台实机已通过。
- 服务器可访问且已有部署授权时，完成备份、部署、检查并记录实际版本；没有权限或访问能力则完成可执行部署交付和其余验证，单列阻碍。不得关闭私人访问控制来方便验收。
- 缺少环境能力不无限等待或反复重试。保护现有未提交改动与正式数据，不强推、不覆盖他人工作。
- 完成有证据支持的部分即可报告“技术完成、部分现场待验”，不把整轮虚报为通过。

## 后续阶段

S0 历史样例保留为接口与持久化证据；本轮补真实使用与接续。跨电脑接续同一任务不等于 S1 跨轮复用。

S1：第二次真实行动实际使用第一轮方法、素材、反馈或判断，留下新产物及采用依据。仅归档、复制或关联不算复用成立。根据实际需要扩展能力视角和视频/工具成果体验，避免为未来一次建全。

S2：真实内容或工具经用户授权对外发布，记录来源明确的反馈、投入、咨询或收入，并影响后续行动。无收入不等于失败；内部审阅不冒充外部效果。

个人信息与能力聚合、大循环继续作为方向。自动平台连接、GPU 调度、画布、全量采集、知识图谱、模型间自动调度和其他项目合并，只有实际场景需要时再规划。

## 协作与文档

GitHub 是规划与执行的共同交接入口，私人站点是运行结果。规划模型负责目标、取舍和独立验收；执行模型负责理解、提出方案、实现与证据；用户参与方向和体验判断，不承担逐项技术转述。
AGENTS 保存长期约定，本文保存当前目标与通过条件，STATUS 保存实际事实与交接。早期想法允许整体合并改写，不把所有远期想法变成当期需求，不靠更长提示词替代执行模型的判断。
阶段报告说明结果证明什么、做过什么取舍、风险与限制；代码实现、线上功能、服务器运行状态分别给结论。
