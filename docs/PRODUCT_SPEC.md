# 产品说明

## 当前产品方向（2026-10-13）

OPC 是 AI 支持的个人发展与一人公司载体：个人是经营主体，Codex 是沟通与执行入口，OPC 承接目标、资源、工作、交付、反馈和理解变化，让 AI 的生产能力与人的理解、探索和判断能力在真实实践中共同积累。求职是可选活动，不能成为产品中心；个人发展也不只以收入或经营活动衡量。

一级结构确定为**个人、个人项目、企业项目、自媒体**。个人承接处境和选择；个人项目承接自主探索与建设；企业项目承接实际业务职责与交付；自媒体承接持续创作、作品、发布和运营反馈。跨板块引用同一材料，video 技术建设和内容经营分别呈现。

现有信息承接继续维护有来源的当前有效状态，后续反馈帮助形成可接受、修改或拒绝的判断。个人愿望、原始材料和模型解释分开，容纳不确定、暂停和目标变化，不生成虚假的能力分数或把生活全部经营化。

2026-10-13 已将下述理解接入项目协作规则、私有当前背景与知识复用入口。这是定位和协作方式的更新，不等于自主探索系统已实现。历史阶段与既有实现见 [开发计划](DELIVERY_PLAN.md)；后续以当前用户任务和 [当前状态](STATUS.md) 为准，不自动执行历史阶段。阶段 2 与阶段 3 第一轮已交付：状态承接 API / Bridge 已上线，四板块工作区页面已接入；阶段 3 第二轮、自动反馈能力与长期效果验证仍未交付。

## 共同成长的判断原则

### 能力与积累

核心期望是“AI 能做得更快更好，人能做得更了解、更会判断”。AI 积累专业工具、成熟生产流程、可复用经验，以及判断何时停止投入的能力；人逐渐扩大见识、发现值得解决的问题、理解关键取舍并识别错误。一次成功项目只是其中一种成果，有限失败留下的认识也可以帮助下一次选择。

模型外的流程、方法、证据与人的理解可以形成长期个人资产，但不能因为保存了资料就宣布能力增长。检验的是它们有没有改变下一次行动的起点、质量、效率或取舍。认知更新可以先发生，生产能力、可迁移优势与人的判断进步分别需要实践证明；不要求每次进步都变成更宏大的产品。

也承接认识为何变化：什么问题、实际体验、质疑与更正使旧想法发生转折，哪些可能性在讨论中才出现。认识变化与探索过程本身可以有价值，不只以最终规则或开发成果衡量；过程解读仍可修正，原始材料缺失时保留缺口，不用后来的概括补造完整经历。

### 探索与执行

用户的想法提供入口，AI 的研究不必止于用户已知的工具或路线。广泛学习面向成熟作品、行业需求、实践方法和专业工具，也可以发现用户未想到的机会、反驳原方案或建议重新审视目标；不能只寻找证明现有想法正确的材料。

开放讨论需要保留尚未表达清楚的可能性，避免过早形成完整开发规划；明确任务则直接推进。双方都不需要永远正确，但判断需要可核对的依据、实际反馈和自我修正。用户同意尝试是授权，不能代替验证；多 AI 意见一致同样不能代替独立证据。

探索与执行可以相互推动。当前路线能实现目标时继续完成，只有全局提升、能力扩展或实际失效才值得重比，不为简单升级反复重构。新的假设也可用有限试验获得证据，但不能为了维护原结论一直追加投入。没有固定的三方挑战流程，也不把每个任务变成 Grill。

### 人的参与与成长

降低用户的表达、操作和协调负担，同时保留成长机会。用户可以先从 AI 完成后的关键判断与成果形成理解，再在合适领域尝试事前判断；不要求先学会全部专业执行才有资格使用 AI。

AI 可结合学习价值、已有理解、意愿和成本建议参与深度，用户可提高或降低。参与记录应说明参与了什么判断、当时依据、实际结果及理解变化，区分参与和掌握；不将讨论频率、审批数量、模型评价或精确分数当成能力证明。主动验证可以利用真实判断，按需进行，不强制课程或考试。

### 反馈、止损与纠错

立项依据回答为什么值得做，后续反馈回答还值不值得继续。反馈不佳时区分执行不足、方法不适合、目标不值得、尚未触达与信息不足；停止投入是一项行动决定，不等于证明整个机会不存在。

停止当前方案后可保留机会与待验证原因，在出现值得尝试的改变、符合当前授权及成本边界时再验证；当前明确的停止要求优先。若持续出现同类失败，要反省 AI 与人的选题、验证和判断方法，不仅提高错误路线的生产速度。记录纠正依据，并通过后续结果检验是否减少同类错误。

### 自主性、知情与控制

理想状态是在明确目标与资源边界内自主研究、试验、分配已授权资源、筛选并创造成果，用户可以按需了解与参与。授权依照具体任务实际确定；讨论中的预算、发布、客户联络与后台探索设想，不构成当前行动权限。

重要发现可以值得知情而不需要马上决策；普通发现保持可查，用户决定看不看、何时参与。未来通知和自主探索要减少注意力负担，不能用频繁审批或提醒证明用户参与。持续商业探索、自动经营、成功项目出售、参与度推荐与能力评测均是待验证方向，不是已有服务或本次自动启动的任务。

## 当前承接方式与验证边界

| 新理解 | 现有承接入口 | 当前能确认的范围 |
| --- | --- | --- |
| 更懂人并支持人的成长 | 私有 `personal-collaboration-preferences` 当前记录 | 可按稳定主题 ID 读取，保留来源与更正历史；不宣称已准确评估人的能力 |
| OPC 的共同成长定位与协作 | 产品说明、AGENTS.md、`personal-opc-direction` | 新任务可获得当前方向；取消固定讨论 / 执行对话 |
| 跨项目学习和判断方法 | 独立知识仓库中的待验证方法条目，既有 context / result | 可同步、检索并引用；返回不等于采用或有效 |
| 现实反馈与纠错 | 项目原始阶段记录、当前状态及历史，关键事件回流 | 能保留依据和变化；不会自动判断项目价值或自主重启 |

最小验证是下一次真实任务能读到新背景和相关方法，并观察它是否改变了有价值的行动；本次写入、同步与读回只证明信息承接成立。若后续需要对照，区分原生能力、当前能力与新增机制，控制任务、模型、资源并用未参与优化的任务检验；不为此立即开发评测平台。

## 当前实现基线

MYOPC 当前同时承载两类入口：一类按固定规程读取独立知识仓库，把需要理解的内容交给模型加工成可直接阅读的说明；另一类展示通过 workspace API / Bridge 承接的 OPC 当前状态、变化、来源与历史。实际实现和运行状态见 [STATUS.md](STATUS.md)，当前待办见 [TASKS.md](../TASKS.md)。

## 分工

| 部分 | 职责 |
| --- | --- |
| 各项目仓库 | 保存代码、项目说明和原始阶段记录，只有一份 |
| 独立知识仓库 | 收集步骤整理出的项目概况、工具说明、个人笔记与跨项目经验（谁执行都可以，不要求单独对话） |
| OPC | 同步知识仓库、建立索引、调用模型生成阅读说明；展示知识页面与 OPC 当前状态；不提供网页正文编辑 |
| Karakeep | 外部文章与资料的收藏层 |
| Easel | 账号定位、内容制作、发布与运营 |
| Project Observer | 解释项目演进与证据 |

分开的理由是内容可以独立保存和使用：换展示工具或让其他 Agent 读取知识时，不必搬动整套应用。

## 页面

- **一人公司 / 变化总览**：按明确项目事件展示进行中、已完成、受阻与显式待决定事项；展示可核对的当前理解并区分用户表达、执行报告与模型推断。
- **一人公司 / 四板块**：个人、个人项目、企业项目、自媒体分别承接主题；详情显示当前头、来源 / 时效、显式跨板块引用与历史技术记录；没有来源的板块保持空白。
- **项目**：知识仓库中的项目概况、来源、仓库或应用入口，以及模型生成的阅读说明。
- **工具**：可调用工具的用途、入口、使用经验与相关项目。
- **空间**：个人方法、经验与判断，可进入原文和加工后的说明。
- **总览**：最近更新的条目、同步状态、待加工数量。

原文、来源和加工结果分开显示；模型推断单独标注，不与原文事实混在一起。

## 加工程序

首版只定义一种加工任务：**阅读说明**。按需组织“解决什么问题、关键选择及依据、操作步骤或适用条件、仍未确定的内容”，不强制填满栏目。

- 程序负责拉取内容、识别更新、解析标题与日期、调用模型、保存结果、记录失败与重试。
- 模型负责把分散材料组织成解释、决策脉络和方法步骤；输出结构化字段并检查来源引用。
- 页面通过固定组件展示，不临时生成结构之外的内容。
- 相同来源与加工规程未变化时不重复调用模型；人工重试或规程更新才重做。

## 记录原则

- 事实、判断与未验证内容分开；没有依据的内容不写入。
- 用户原话与直接报告可标为 `origin=user / assertion=reported`；AI 对个人或转折意义的综合理解使用 `origin=agent / assertion=inferred`。共同形成并应用的暂时工作结论可由 AI 报告，注明采纳依据，不伪装成用户逐字表达；用户转交的外部复核保留其来源性质。
- 页面展示结果不覆盖知识正文；知识修正在知识仓库里完成。
- 模型失败时保留上一次可用结果或原文，并显示处理状态。
- 示例、模拟数据与真实结果区分，不编造发布、收入或验证状态。
- 个人能力与方法记录属于私有运行数据，通用方法可整理进知识仓库。

## 边界

- 不复制 Karakeep 的收藏功能，也不复制 Easel 的编辑器与账号后台。
- 不建网页编辑器与 Git 双向同步；修改内容走知识仓库。
- 首版不做知识图谱、向量数据库或多 Agent 调度平台；按真实需要再增加。
- 历史业务数据（素材、行动、成果版本、反馈）保留可查，不再作为主要流程。
