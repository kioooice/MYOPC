# 产品规格 v0.2

状态：建设目标与范围基线；不是已实现功能清单。
日期：2026-09-06。

## 1. 目标与判断标准

用户持续发现、收集和培养能力，并希望将能力用于具体行动，逐步获得副业收入。MYOPC 的主线是“能力收集与培养 → 实际应用 → 成果与反馈 → 能力改进”，项目是能力使用与检验的场景。
能力可来自实践帖、技能、工作流、开源工具及用户自己的经验记录；不限定为模型可执行的 Skill，也不将个人能力简单等同于工具清单。
用户负责方向、审阅、采用与经营判断；Codex 负责主要执行；MYOPC 保存和呈现结果。

核心价值：
1. 能随时低负担收集能力线索，看清能做什么、如何用、缺什么，并进入实际试用。
2. 不必遍历对话和文件夹才能找到当前成果。
3. 在面板留下的反馈能被 Codex 准确接续。
4. 能区分在做什么、完成了什么、实际对外发生了什么。
5. 多方向使用一致的底层记录，但成果呈现适应业务。

不将收入目标硬编码，也不强制只允许一个项目。活动项目数量是可见信息，由用户决定投入。

## 2. 业务对象

| 对象 | 含义与关系 |
| --- | --- |
| 收集条目 Capture | 链接、文件、文本或自述的原始输入，可独立存在，保留来源与读取状态 |
| 能力 Capability | 能完成一类事情的方法与条件，不要求关联项目；可来自用户自身、工具辅助或 Codex 执行 |
| 方法版本 CapabilityRevision | 某次适配后的步骤、输入输出、环境、依赖、限制和来源快照；修改产生新版本 |
| 试用 Trial | 对某方法版本的一次实际验证，记录环境、输入、成本、结果和证据；可以没有项目 |
| 应用记录 CapabilityUse | 将具体方法版本用于某项目/工作项/成果版本，保留使用关系与效果 |
| 方向 Track | 内容运营、视频创作、小工具等可编辑分组；渠道不是方向的固定替代 |
| 项目 Project | 一次具有目标和判断条件的经营尝试，归属方向；不是代码仓库的同义词 |
| 工作项 WorkItem | 项目内需要完成的工作，可关联成果；仅为执行辅助 |
| 素材 Asset | 可复用的文本、图片、视频、链接或文件，记录来源 |
| 成果 Deliverable | 稿件、视频、工具等持续存在的业务对象 |
| 成果版本 Version | 不可覆盖的具体内容快照，关联输入素材与前序版本 |
| 反馈 Feedback | 对特定版本的意见、处理状态和处理它的新版本 |
| 发布记录 Publication | 某版本在某渠道的实际发布；保存日期、链接和用户提供的证据 |
| 投入与结果 Entry | 金钱、时间、观察指标，关联项目及可选发布记录 |
| 决策 Decision | 继续、调整、暂停等判断及其依据 |
| 活动 Event | 哪个主体在何时更新了什么，用于接续和审计 |

一份内容可以有多个平台适配成果，每个平台成果有自己的版本。公众号与小红书稿件关联同一内容项目。一次发布必须锁定具体版本，不能随最新版变化。

金钱记录保留币种，不直接跨币种求和。未知投入显示未记录；空播放量不是零播放。指标记录平台、统计周期、采集时间和来源，不跨平台直接计算统一互动率。

能力与项目多对多关联。试用成果可通过 Trial 归属，无须创建虚假的经营项目；同一成果可被后续项目引用。投入 Entry 可关联 Trial 或 Project，同一支出不得因复用重复统计。
来源事实、Codex 提取的判断和实测结论分别保存。原链接不可读时保留条目并标明未读取，不推断教程步骤。独立能力与项目均可归档，已引用的方法版本和来源不得随之丢失。

## 3. 页面与交互

### 经营总览

第一屏：值得推进的能力试用、活动方向与项目、需要用户处理的成果、近期变化。提供随手收集入口；新用户没有项目时也能开始。投入结果作为辅助信息，初期无数据时不摆放虚假 KPI 大卡片。

- 项目卡片突出目标、当前阶段、最近成果缩略图和下一项待处理事项。
- 点击成果直接进入预览，点击项目进入工作区。
- 用户可修改优先级、暂停项目，保留历史。
- 全局导航：总览、能力、项目、成果、素材、复盘；收集入口常驻，设置单独放置。
- 不放 Agent 员工、模型排行榜、终端日志作为主视觉。

### 能力工作区

能力与项目并列，首页卡片突出“能完成什么”、可见成果样例、试用情况、缺口与下一步；不展示虚构能力分数，不以列表字段替代详情体验。

- 随手收集：只需链接、文本、文件之一；标题可后补，来源可记录“本人经验”。无需先选项目、分类或填预算。
- 整理详情：原始来源、Codex 提取的方法、用户补充、实测结果可区分；看得见具体示例与产物。
- 可用条件：输入输出、步骤、环境、依赖、成本参考、适用限制按需补充；未知标未知。
- 行动入口：“补充/适配”“开始试用”“用于项目”“记录结果”。开始试用创建意图与上下文，Codex 下次读取后执行，不在网页暗中唤醒 Agent。
- 试用可独立进行并展示成果、反馈与投入；不强制先完成所有档案字段。
- 用于项目时选择已有项目或创建新项目，引用方法版本，沿用其输入条件；不是复制一份脱离来源的笔记。
- 培养记录显示尝试了什么、失败在哪、改进了什么、下一步缺什么。新方法版本不会继承旧版本的已验证结论。
- 能力组合先用简单有序步骤和依赖引用表达，锁定组成能力版本；各部件成功不等于组合流程成功。首轮不建可执行工作流引擎。

转化出口：个人可复用方法、具体成果、可交付的技能包/产品/服务。最后一项不是强制出口，是否可出售由实际验证决定。

### 项目工作区

上方展示目标、验证条件、状态与投入上限（可空）；主体以成果和当前工作为中心。
提供概览、成果、素材、所用能力、记录入口，反馈在相关成果旁处理。所用能力可回到对应方法版本与试用证据；项目经验可以提出能力改进版本，不能自动覆盖原方法。
工作清单可折叠；技术执行细节放在下钻位置。

图文：完整阅读、平台适配版本切换、版本比较、批注。
视频：可播放预览、脚本与参考素材、版本缩略图、生成参数摘要及来源；第一版不做剪辑器或时间线编辑器。
工具：用途、可用版本、体验链接或下载、已知限制与反馈；外部预览不能嵌入时明确提供新窗口入口。

### 成果详情

- 明确显示当前查看版本与已采用版本，二者可以不同。
- 反馈绑定版本，第一版支持整体意见与引用片段，不强做精确坐标批注。
- 新版本提交后，旧版本仍可查看，未解决反馈仍可发现。
- 采用版本是一个独立动作；成果采用不自动变成已发布。
- 删除优先归档；被发布记录引用的版本不能直接硬删除。

### 素材与复盘

素材支持缩略图、类型筛选、来源、被哪些成果使用。
复盘展示实际投入、发布记录和观察，允许记录没有效果、暂停和失败。
图表只用于真实可比较数据。费用包含生成成本、软件/服务支出等，由记录来源决定，不从 token 数臆算订阅消费。

## 4. 状态设计

能力整理状态：inbox / developing / available / archived（available 表示已整理可尝试，不代表验证通过）。
方法验证结论单独显示：unverified / succeeded_once / repeated / needs_recheck，必须附对应版本、环境和实际试用记录；失败/阻碍在 Trial 记录为 failed / blocked，不抹掉已有成功证据。repeated 至少有两次独立成功试用，但仅说明记录范围内的重复成功，不承诺普遍可靠。
能力自述保留为 self_reported，不能冒充系统实测。新版本默认 unverified；更换关键依赖时标待复验。能力可先应用再补充记录，状态不能变成繁重人工 Gate。

项目：planned / active / paused / completed / archived。
工作项：todo / in_progress / blocked / done / cancelled。
成果审阅：draft / ready_for_review / changes_requested / accepted。
反馈：open / addressed / resolved；Codex 可以标为已处理并关联版本，用户决定是否解决。

版本提交不得自动替用户接受成果。
工作项 in_progress 只表示工作阶段，不能据此声称进程仍在运行。
第一版显示最后更新时间和最近执行说明；没有心跳不展示实时运行灯。
发布单独记录，不能用 accepted 推断 published。

## 5. 第一版完整用户故事

0 能力：随手收集实践资料或自己的方法 → Codex 提取用途和条件 → 适配为方法版本 → 独立试用并写入成果 → 用户反馈 → Codex 改进方法 → 在项目应用并关联结果。至少覆盖外部资料与本人经验两种来源；H3 是示例，未指定实际帖子，不编造其内容。

A 图文：创建一个内容项目 → Codex 保存两种平台稿件 → 阅读并给小红书版本提意见 → Codex 更新该成果 → 用户采用 → 用户记录发布链接。
B 视频：关联脚本与参考图 → Codex 导入实际生成的视频及来源 → 用户播放并比较版本 → 选定成片。生成可在系统外完成。
C 工具：Codex 关联实际可体验版本 → 用户体验并反馈 → 新版本与已知限制同步到工作台。面板不承担构建和发布。

能力试用与三类项目故事共用成果、反馈与版本机制，避免分别建设四个系统。首版必须能从项目结果回看所用方法，也能从能力回看多个应用。
第一轮可使用明确标记的测试素材验证技术链路，随后至少完成一条真实经营尝试；发布仍由用户主动操作。

## 6. 明确不做

首轮不做：多用户团队与复杂权限、社交平台自动发布/登录托管、内容推荐算法、站内通用聊天、Agent 调度、自动招聘角色、GPU 租赁控制、全量对话监听、复杂财务系统、无限画布总首页。

暂缓：跨项目知识图谱、自动经营建议、平台指标自动采集、Observer/Helm 集成、复杂全文检索。每项须由真实使用缺口触发。

## 7. 参考与设计决策

- Backlog.md：可参考机器更新与人类界面共用记录；其任务中心不足以覆盖本产品。
- Baserow / NocoDB / Notion：数据组织有参考价值，但不能用数据库视图代替专属业务体验。
- Paperclip / OpenOPC：组织和调度 Agent 与本产品定位不同，不引入。
- infinite-canvas：https://github.com/tigerowo/infinite-canvas
  参考成果可视化、输入输出关系和版本比较。其 README 明确仍在开发且不保证历史数据兼容，不能直接承担经营记录底座。
  首轮只做简单来源列表；是否需要局部画布，由真实视频工作量验证。
- 复用第三方代码前确认依赖与许可，记录来源；本规划不等于授权复制整套项目。

## 8. 产品验收底线

中文、桌面浏览器优先；1366×768 与 1920×1080 下核心操作可见，无文字截断和遮挡。
有加载、空状态、失败、断线、附件失效与重试入口。
首次进入能直接收集能力线索、开始试用或创建项目，不要求先学习数据库、模型或 Agent 概念。
没有生成内容时不调用模型填充假成果，不用图片生成代替真实产物。
