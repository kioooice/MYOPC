# 产品规格 v0.3

日期：2026-09-07。
状态：可修订设计，不是已实现功能清单。产品意图与记录真实性已明确，导航、对象和状态均为待场景验证的方案。

## 1. 产品主线：持续改变下一轮的起点

MYOPC 帮助个人让信息、知识、能力、资源、行动和结果形成大循环：
发现与输入 → 结合个人积累 → 形成尝试 → 实际行动 → 结果与反馈 → 更新积累 → 下一次选择与行动。

入口不固定：看到 H3 实践帖、想做一期内容、获得一个技能、已有成果或遭遇失败，都能开始。
这些环节不对应六套独立系统，也不要求依次填表、审批或先创建项目。
能力循环回答能否完成以及怎样改进；价值循环回答对谁有用以及是否值得继续投入。个人学习不必立即变现，经营尝试仍需接触真实外部反馈。

用户负责目标和关键判断；Codex 帮助连接积累、提出有依据的方案并执行；工作台保存对象、关系、成果与变化，不自主推理或调度另一个 Agent。
个人信息仅纳入影响当前判断的目标、偏好、资源限制与经验，初版不建设全面个人数据仓库。

## 2. 用场景检验结构

### 场景 A：由发现进入
收集实践资料 → Codex 对照已有目标、方法和素材判断适用机会 → 选择一个小试验 → 产物与反馈 → 改进方法或限制适用范围 → 第二次实际应用。
来源未读取时不编造步骤；H3 仅是例子，未给出具体帖子。S0 可用低成本图文资料替代视频生成。

### 场景 B：由需求进入
提出内容/工具目标 → 找到相关的既有方法、素材、失败经验 → 说明采用与不采用的理由 → 行动并产生结果 → 反馈修正后续选择。
无需为了符合流程再建一条收藏或一份能力档案。新需求可以复用旧方法，不重复维护副本。

### 场景 C：由失败或结果进入
结果出现问题 → 保留事实证据 → 区分可能原因（方法、环境、投入、选题或需求）与已验证原因 → 选择下一次调整 → 再执行并比较。
效果不佳不自动归咎技术，也不直接判定市场无价值。证据不足时保留假设。
通过减少投入、调整用途甚至停止一个方向，也可以积累有用判断；未再次执行的暂停决定不冒充第二轮验证通过。

共同验收：第二次行动确实使用了第一次留下的材料/方法/判断，发生了有依据的变化。不得为了显示“循环完成”强迫每次修改已经有效的方法，也不得只靠 AI 总结证明改进。

## 3. 信息与业务关系（候选模型）

| 角色 | 保存内容 | 如何连接循环 |
| --- | --- | --- |
| 输入 Capture/Asset | 来源链接、文本、文件、自述、读取状态 | 可关联目标、尝试、方法与成果，不要求先分类 |
| 能力 Capability/Revision | 用途、方法版本、条件、缺口与验证证据 | 可先收集后整理，也可由行动中提取 |
| 尝试 Trial / 项目 Project | 目标、所用资源、行动、投入、结果 | 小试验不强迫建经营项目；项目并非代码仓库同义词 |
| 应用 CapabilityUse | 所用方法版本、素材及对应成果 | 多项目共用能力，历史引用不随新版本漂移 |
| 成果 Deliverable/Version | 稿件、视频、工具及版本 | 可从项目、试用、素材、能力视角访问同一成果 |
| 反馈与观察 Feedback/Entry | 用户意见、外部效果、成本与来源 | 明确对应结果、版本、时间和条件 |
| 决策 Decision | 依据、解释、调整或保留的内容、下一步 | 下一次行动引用它，形成可回溯循环 |
| 发布与活动 Publication/Event | 实际发布版本和操作历史 | 区分展示、采用、发布与市场效果 |

表中名称是实现候选，不要求一项一个页面或一张表。先验证场景，再确定 S0 的最少数据结构。
稳定对象标识、不可覆盖的历史内容和可追溯关系保留；枚举、字段和 API 路径可调整。
一次尝试留下的素材、方法、结果可在不同视角使用，不要求用户分别重复录入。
个人通用方法与企业内部数据分离；公开代码仓库不保存个人运行数据。

## 4. 交互原则与候选页面

### 总览
回答“当前值得推进什么、什么需要我判断、上次结果改变了什么”。
入口支持随手输入与已有目标，不把收藏数或能力总数作为主 KPI。
推荐与关联由 Codex 提供并附理由、来源和更新时间；面板不制造实时智能推荐。
能力、项目、成果、素材、复盘可作为导航视角，但不能强迫跨多个页面才能完成一件事。导航数量在原型验证后确定。

### 连续工作区
围绕当前尝试聚合目标、相关能力与素材、当前产物、反馈和下一步。
可从输入、项目、能力或结果进入；既有关系直接可见，缺口按需补充。
用户可以预览、比较、批注、选版本、调整优先级、暂停、关联下一次尝试。
这些动作通过业务记录供 Codex 下次读取，不假设按钮能唤醒当前对话。

### 能力与个人积累视角
突出能做什么、条件、实物样例、实际用过哪里、最近改进与失败边界。
链接/文本/文件之一即可收集；自述经验保留来源，不冒充系统实测。
方法档案渐进完善，不强制完整填写后才能试用。
组合能力先用简单步骤与版本引用，不建工作流引擎；部件成功不等于组合已验证。

### 成果与反馈视角
图文：完整阅读、平台适配稿切换、版本比较。
视频：播放、素材和脚本关联、版本比较；首轮不做剪辑器或导演台。
工具：用途、可体验/下载版本、限制与反馈；外部链接无法嵌入时新窗口打开。
当前查看、已采用、已发布版本明确区分，反馈绑定具体版本。
反馈可以同时产生本次修改和下一轮调整；后者保留依据、目标尝试与实际执行状态。
复盘要能进入下一步行动，而不只生成一篇归档文档。

## 5. 状态与事实边界

状态名称在实现时精简；必须区分：
- 已收藏、已整理可尝试、本人自述、实际试用成功、失败、待复验。
- 方法版本变化后不得自动继承验证结论；多次成功只说明证据覆盖的条件。
- 尝试/项目业务进度与真实进程状态；无心跳只显示最后更新时间。
- 草稿、待审阅、要求修改、采用；采用不自动变成发布。
- 反馈已回复、已处理、已解决；用户决定接受，Codex 记录处理证据。
- 拟议调整与已实际用于下一轮；记录关联不等于执行成立。

发布锁定成果版本。收入、成本保留币种，观察指标保留平台、期间、来源和采集时间。
未记录与零值区分；跨平台不直接计算统一互动率；复用不能重复计算同一支出。
个人收益、技术可用和商业效果分别表达，不生成统一能力分数或成功率。

## 6. 范围与验收底线

第一版单人、中文、桌面浏览器优先；核心页面在 1366×768 和 1920×1080 无遮挡。
支持空状态、加载、断线、错误、附件失效、归档和恢复；引用中的旧版本不直接硬删除。
不自动发布、不接管账号、不创建第二个 Agent、不暗中执行收藏的技能或软件。
暂缓自动指标采集、GPU 控制、通用知识图谱、全量个人信息采集、复杂财务、多用户、全屏无限画布及现有项目合并。
只把对当前场景有具体价值的缺口纳入下一阶段。

核心验收单位是一圈可复用的实际过程，功能清单用于支持该过程。演示数据和真实经营数据严格区分，不能用模拟发布补齐商业闭环。

## 7. 参考与取舍

已考察 Backlog.md、Baserow/NocoDB/Notion 与 Paperclip/OpenOPC：不将任务看板、数据库视图或 Agent 调度平台作为产品形态。
自建业务体验，复用成熟编辑器、播放器、存储及 UI 组件。
https://github.com/tigerowo/infinite-canvas 参考成果可视化、素材与来源关系，不默认复制其 Agent 或整体系统；首轮不必建设画布。
参考选择可以随具体证据调整。复用代码前核对依赖和许可。

## 8. 文档的确定程度

已明确意图：个人积累与行动形成循环、Codex 驱动而面板承载、当前副业主线、低负担输入、真实可追溯记录。
当前方案：本文件中的页面、对象、状态和阶段划分。
待验证：实际连接方式、跨轮接续体验、用户是否减少重复操作、哪些信息真正改变下一轮判断。

这些区分表达当前确信程度，不是永久冻结。新想法改变整体理解时，整体重写相关方案并清除冲突。
